# 声明式图可视化架构——可复用的前端方法论

> 从"基带IP信号流图"项目提炼，与业务无关。适用于任何"节点+连线+语义规则"的可视化编辑器：
> 网络拓扑、工作流编排、信号/管线路由、组织架构、知识图谱等。

## 一句话

**用一份 JSON 描述"世界是什么"，其余一切（画布、两种视图、AI、校验、撤销）都是它的纯派生物。**

## 五层架构

```
┌─────────────────────────────────────────────┐
│ 1. 规范层：数据模型文档 + 三端 schema 同步    │  docs/schema.md + zod/pydantic
│    （唯一事实源的字段语义，AI/人/测试共读）    │
├─────────────────────────────────────────────┤
│ 2. 本体层：规范化 JSON（SignalGraph）         │  只描述"有什么"，不含任何渲染信息
├─────────────────────────────────────────────┤
│ 3. 推导层：纯函数                             │  trace/graph→视图数据，无副作用可单测
│    - 视图推导：本体→画布节点/边              │
│    - 语义推导：追踪算法→流路径               │
│    - 派生数据：镜像/跟随/清理规则             │
├─────────────────────────────────────────────┤
│ 4. 编辑层：集中 action（唯一写入口）          │  store action：校验+派生规则+撤销快照
├─────────────────────────────────────────────┤
│ 5. 渲染层：纯派生画布                         │  画布永不反向修改本体
└─────────────────────────────────────────────┘
```

## 核心原则（按重要性排序）

### 1. 本体/视图分离
- **本体**（存库）：实体、关系、语义属性。字段名给人和 AI 看，不给框架看。
- **视图**（分开存）：坐标、视口、缩放。丢了可自动重排。
- 检验标准：把视图层全删掉，本体仍然完整描述业务。

### 2. 画布是投影，不是状态
- 节点/边数组由本体 `map()` 派生，每次编辑重建（本项目中 `rebuildCanvas()`）。
- 画布只允许回写两样东西：**坐标**（进视图层）和**用户意图**（转成 action）。
- 收益：撤销 = 恢复本体快照（深拷贝），渲染自动跟着对；无双向同步 bug。

### 3. 编辑必须过 action 层
- 所有修改（UI 拖拽、对话框、AI、右键菜单）走同一组 store action。
- action 里集中做：规则校验、派生数据维护、撤销快照、失效清理。
- 组件里直接改 store 数据 = 架构破坏（lint/review 拦住）。

### 4. 业务派生关系显式建模
真实业务充满"跟随"关系，把它们定义成幂等函数，挂在所有变更路径末尾：
```
syncAfterEdit() {
  改址跟随（按实体 id 追踪"改名"而非"删了又加"）
  → 失效关系清理
  → 孤儿数据清理
  → 镜像刷新
}
```
派生侧 UI 只读（让用户形成"改源头、全局跟随"的心智模型）。

### 5. 多视图 = 同一本体的多个推导函数
- 视图A（物理）：本体→全部实体。
- 视图B（语义）：追踪算法（纯函数）沿"关系+属性"走出路径，再映射到画布。
- 两个视图共享坐标（切换不跳位），各画各的边。
- 追踪算法务必**纯函数**：输入本体输出路径，可单测、可给 AI 当上下文。

### 6. AI 对接 = 操作协议，不是整图输出
- LLM 不输出整份 JSON（会幻觉、会丢数据），输出**操作列表**：
  `{reply, ops: [{op:"connect", from:{name,port}, to:{name,port}}, ...]}`
- 每条 op 独立校验、可部分失败；引用实体用人类可读的名字（name+编号），
  前端解析成稳定 id。
- 本体本身就是 AI 的上下文（无渲染噪音，序列化即提示词）。

## 渲染层实战技巧（画布引擎通用）

| 问题 | 解法 |
|---|---|
| 多线共享一个端口时重叠 | **端点不动、控制点偏移**：贝塞尔控制点沿垂直方向按序错开（系数 4/3 保证中段张开≈偏移量），两头自然汇聚到端口 |
| 扇形槽位错乱 | 槽位按**对端节点几何位置**排序分配（上面的设备占上面的槽），不按数据顺序 |
| 正反向线叠同侧 | 垂直基**方向归一**（恒取朝右/朝下半边），正反向共用基准 |
| 标签飘离线 | 标签取贝塞尔 t=0.5 中点 + ≤8px 微调，别用端点均值近似曲线 |
| 边点击难命中 | 在标签渲染层（EdgeLabelRenderer 等 HTML 覆盖层）放**隐形热区**，绕过 SVG 命中测试和框架事件链 | 
| 长线走向突兀 | 曲率 = 距离×系数，必要时封顶，让所有线进近量一致 |
| 颜色区分度差 | 哈希取色用 **FNV-1a**（弱哈希对相近字符串产生连号色相）；语义色（如方向）优先级高于哈希色 |
| 键盘快捷键在中文输入法下失效 | 用 `e.code`（物理键）判断，别用 `e.key`（IME 时是 "Process"） |

## 技术栈选择（本项目实证）

- **Vue3 + Pinia + VueFlow**（画布引擎）+ element-plus（UI）
- **zod / pydantic** 双端 schema + 契约夹具往返测试锁一致
- SQLite(WAL) 单文件库，API no-store（数据频繁变更的可视化工具禁浏览器缓存）
- 后端 FastAPI 工厂模式，`--factory` 启动

## 什么信号说明你正在偏离这套架构

1. 组件里出现 `store.graph.xxx = ...`（绕过 action）
2. 画布对象里混进了坐标以外的业务字段
3. 撤销需要"反向操作"而不是快照恢复
4. 两个视图各存一份数据
5. AI 直接改画布 / 输出整图
6. 派生数据（跟随/镜像）靠用户手工保持一致
